# トメリス v0.26：本文根拠付きの調査報告

アプリを閉じ、いつものアイコンから開き直してください。明るい画面・天気・計算・記憶・計画の機能を維持しています。

## 試す例
- `ジャービスに関するサイトを出して` → 対象を尋ねられたら `アイアンマン`
- `調査: Ollama`
- `https://ollama.com/ 何ができるか調べて`

自動検索・ネット検索・情報収集は、今回から本文を取得して出典付きで報告します。URLを入力した場合は検索を介さず、その公開ページを読みます。通常の「会話」は外部検索しません。

## 報告の仕組み
1. 現在対応している曖昧語「ジャービス/JARVIS」では、アイアンマンのAIか実在する製品かを確認します。一般の曖昧語すべてを判定するものではありません。
2. テーマと「テーマ 公式」の2検索を使い、重複を除き、関連語が多い候補から最大3ページを取得します。同じホストからは最大2ページです。「公式」の検索語だけで公式情報だと認定しません。
3. HTMLまたはテキスト本文から質問に関連する箇所を抽出します。検索結果の抜粋だけを根拠に結論を作りません。
4. ローカルAIが日本語で整理する場合は、各項目に取得済みの根拠IDを指定させます。根拠IDが存在すること、数値が引用にあること、URLを生成していないことを確認します。引用はプログラムが原文から添えます。
5. 検査に通らない要約は表示せず原文だけを表示します。本文を取得できない場合はその理由を表示します。
6. 出典URL、取得日時、確認できた場合のページ記載の掲載日、未確認事項、取得できなかったページを表示します。

## 正確さの限界
「出典に書かれていた内容」と「事実として正しい内容」は同じではありません。意味の一致・最新性・公式性・複数情報源の独立性を自動で保証していません。ローカルAIの整理は引用と照らして確認してください。構造的な検査は、意味の誤りをすべて見つけるものではありません。

検索サービスBingのRSSには無関係な結果が返る問題があり、今回の実通信でも再現しました。DuckDuckGoの通常のHTML検索も自動取得制限があり、この版では利用していません。信頼できる検索結果を毎回確保する問題は未解決です。対象ページのURLが分かる場合は、URLと質問を入力すると検索の問題を避けて本文を調べられます。

取得範囲は最大3ページ、各1MB、本文先頭50000文字。JavaScript実行、ログイン、PDF、圧縮応答には未対応です。通信の目安は1ページ15秒で、名前解決等で長くなる場合があります。関連箇所の選択はキーワードベースで、質問の全項目に必ず答えられるわけではありません。掲載日の表示はページの記載であり検証済みではありません。

## 外部送信と保護
質問から作った検索語をBingへ送信します。出典ページの取得では、そのURLと通常のGETリクエストだけを送ります。保存済みの記憶・過去会話は検索先やページの提供元へ送りません。要約する本文はローカルOllamaに渡します。
公開IPだけに接続し、解決した公開IPへ接続先を固定します。転送先も毎回検査し、ローカルネットワーク、認証情報入りURL、任意ポートを拒否します。アクセス制限や認証画面の回避は行いません。読んだページ内の指示をアプリ操作として実行する機能はありません。
報告できた内容は通常の会話履歴に保存します。長期記憶への自動登録は行いません。
