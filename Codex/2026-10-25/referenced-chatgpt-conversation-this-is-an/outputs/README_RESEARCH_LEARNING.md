# 調査精度と報酬学習の実験（v0.72）

ユーザー指定の優先順は11番（強化学習）と9番（情報収集）。顔認証・利用者分離は残件として保持する。

## 今回通常起動へ入れるもの
別URLで取得した原文が同一なら、追加の根拠・保存資料として重複計上しない。空白とUnicode表記を正規化して照合し、表示引用は取得原文のまま。新しい記述は残す。この検査は出典の独立性・事実の真偽・矛盾の解決を認定しない。ネットワークの追加呼出しはない。

## 報酬学習は通常起動から切り離した実験
`tomeris_bandit_lab.py` は文脈付きバンディットのシミュレーション。概要／具体的質問という2文脈、検索順／対象名一致優先という2方針の価値を、選択した方針への報酬だけから更新する。20%の確率で探索し、乱数種を固定して再現可能にする。各学習例を20回提示。試行ごとに対象ID・選んだ方針・報酬を記録する。

評価用の対象は学習用と重複させず、評価用の報酬は学習に使わない。評価時は両方の方針の報酬が判明しているデータだけを受け付ける。未観測の報酬をゼロで埋めることはしない。これは部分観測の実運用ログに対するIPS／DR評価ではなく、全方針を採点した環境でのシミュレーションである。

付属 `bandit_synthetic_examples.json` は人工データ18行（学習12・評価6）。報酬は実検索の採点ではない。結果は実験用固定方針との比較であり、既存アプリは既に概要優先などの処理を持つため、現行アプリに勝ったことを意味しない。Ollamaの重み、人格、記憶、PC操作権限は変更しない。通常起動は実験結果を読み込まない。`production_enabled` は常にfalse。

実行例（outputsフォルダーのPowerShell）：
```
py -3 -B .\tomeris_bandit_lab.py .\bandit_synthetic_examples.json --output .\bandit_trial_01.json
```
出力先が存在する場合は上書きせず失敗する。再実行は別名を指定する。実験はネットワークもモデル呼出しも行わない。

## 今回確認したこと
人工報酬では概要→対象名一致優先、具体的質問→検索順が選ばれた。評価平均報酬1.0、実験用検索順固定0.5。人工的に与えた報酬表上の数字であり、正答率・実検索成功率・知能の点数として使用しない。

## 次に必要な作業
1. 実検索の候補と本文を、取得日時・方法・対象名付きで比較用に記録する。
2. 独立した採点で、質問への適合、日時、根拠の一致、誤った同名対象、重複などを評価する。AI自己評価だけを正解ラベルにしない。
3. 未使用の対象と、現在のアプリそのものを比較対象にして評価する。誤り率と取得できなかった割合も記録する。
4. 検証済み方針の限定適用・元に戻す仕組みを作る。重みの強化学習はさらに別の工程とする。

## v0.73 実検索の比較記録と採点画面
「資料学習 → 調査を比較・採点（実験）」から、Wikipediaの公開テーマを指定します。最大3候補を一度ずつ取得し、検索順と対象名一致優先の先頭1候補を比較します。両方が同じでもそのまま記録します。通常の調査とは独立した実験で、既存の検索方法設定を変更しません。最新・速報などの質問とURL指定はこの実験では受け付けません。

候補、本文、抽出原文、出典、取得確認日時、記事の更新日時、失敗理由を research_trials フォルダーへ保存します。本文は最大50,000文字／記事です。原文を含むため、このフォルダーは公開資料の作業用キャッシュとして扱ってください。記憶・過去会話は送信しません。表示したページの内容は命令として実行しません。

採点は初期状態「未採点」。本文を確認して各方針を不適合／一部適合／適合で評価し、理由を記入して別ファイルに保存します。レビューには対象記録のハッシュを付け、記録変更時は採点を拒否します。ハッシュは内容対応の確認用であり、評価者の本人認証や悪意ある改変の防止を保証しません。空の候補記録を採点して学習の正解とすることはできません。

比較記録・採点は現在の通常バックアップ対象外です。research_trialsフォルダーに独立して保持されます。採点はまだバンディット学習へ自動投入されません。次は採点済みの記録を検証し、対象が重ならない学習用／評価用データへ書き出す工程を作ります。

## 採点済みデータの書き出し（2026-11-05）
`tomeris_trial_export.py` を追加。記録フォルダー内の比較記録とレビューのファイル名、対象グループ、学習／評価区分を選択表で明示します。訂正レビューが複数あっても最新を勝手に選びません。1試行につき一つだけ選択してください。

選択表の形式（下記のファイル名は例です。実際に保存した名前へ置き換え、4件以上を選択）：
```
[
  {"record":"記録ID.json","review":"記録ID.review.評価ID.json","topic_id":"同じ対象をまとめる識別名","split":"train"}
]
```
`split`はtrain（学習）かtest（評価）。両区分それぞれにoverview（概要）とspecific（具体的質問）の試行が必要です。同義名・表記違いの対象にも同じtopic_idを指定してください。グループ名・正規化した検索語・先頭資料URLのいずれかが学習と評価に跨る場合は拒否します。ただし、異なる名前やURLでも同じ対象・転載資料であることを完全には自動判定できません。

実行例（outputsフォルダー）：
```
py -3 -B .\tomeris_trial_export.py .\tomeris_desktop_data\research_trials .\trial_selection.json --output .\reviewed_dataset_01.json
```
別データで起動している場合は記録フォルダーをその保存先に変更してください。出力は既存ファイルを上書きしません。バンディット実験への入力にできますが、書き出しだけでは学習も本番適用も行いません。

記録と採点のハッシュ対応、両方の採点・理由、両方の先頭資料の取得成功、引用が本文に存在することを検査します。同じ先頭資料なのに異なる点数が付いている場合は拒否します。取得失敗の研究も重要ですが、現段階の書き出し対象は両方の本文を取得できた試行に限るため、これだけで全検索の成功率を評価できません。

出力には記録・レビューのハッシュと出典URLを付けます。ハッシュは資料と採点の対応確認であり、評価者本人の認証・評価内容の正しさの保証ではありません。この機能は現在は開発用コマンドで、アプリ内の選択画面は未実装です。

## v0.74 アプリから選択・分類・書き出し
再起動後、「資料学習 → 採点済み資料を学習用・評価用に分ける」を開きます。
1. 評価記録を選び、点数と理由を確認します。
2. 同じ対象をまとめるグループ名と「学習用」または「評価用」を指定し、「この評価を採用」を押します。
3. 学習用・評価用それぞれに概要と具体的質問が入るよう、4件以上を選びます。
4. 「検査して新規ファイルに書き出す」を押します。不整合があれば画面下に理由を表示します。

初期状態はすべて未採用。同じ試行の別レビューを採用するときは、先に現在の採用を取り消します。記録のハッシュや本文は書き出す際に再検査します。選択状態はこの画面内だけに保持し、閉じると解除されます。出力はローカルの新規JSONで、学習や通常回答への適用は行いません。記録なしの場合は先に「調査を比較・採点」で資料を取得して評価を保存してください。

## 画面からオフライン実験する（v0.75）
「資料学習 → データセットで学習実験（通常回答には未適用）」から、前の手順で書き出したJSONを選びます。採点済み資料は元のresearch_trials内の記録・レビューとの対応を再検査するため、元資料も必要です。結果画面では方針と評価件数、平均報酬、実験用の検索順固定との差を確認でき、結果だけを新しいファイルへ保存できます。

人工データの動作確認はbandit_synthetic_examples.jsonを選択します。「人工データ」と明示され、実検索の能力向上の証拠にはなりません。採点済み記録と人工データの混合は拒否します。取得失敗例はこの評価に含まれず、平均報酬は正答率ではありません。通常検索への適用・モデル重みの変更は行いません。

## 画面で成功・失敗を見る（v0.76）
「資料学習 → 比較試行の成功・失敗を見る」から、保存済み比較記録を確認できます。未採点や取得失敗、不正記録も表示します。集計日時は画面を開いて集計した時刻で、各資料の取得時刻とは異なります。読むだけの画面で、再取得や採点、学習実行はしません。通常の調査履歴全体ではなく、比較実験の保存試行が対象です。

## 評価への資料混入の検査範囲
先頭資料だけでなく、採点画面で参照できる下位候補・全順位・取得本文のURL・取得失敗の記録URLも、学習用と評価用で重ならないよう検査します。重なる場合は関連する試行を同じ区分にまとめ、評価用には別の対象を選んでください。既存データを書き換えることはありません。別URLの転載や表記違いを全て見抜けるものではないため、対象グループの明示分類も必要です。

## 比較記録・採点の専用バックアップ
通常バックアップの対象外だったresearch_trialsを別ZIPとして保存・検査する開発用コマンドです。outputsフォルダーで、トメリスの比較・採点処理を終えてから実行します。

```powershell
py -3 -B .\tomeris_trial_backup.py create .\tomeris_desktop_data\research_trials .\research_trials_backup_01.zip
py -3 -B .\tomeris_trial_backup.py inspect .\research_trials_backup_01.zip
```

既存ZIPは上書きしません。比較記録・採点JSONの元バイトと一覧・サイズ・SHA-256を保存し、検査は展開せずに行います。不正なJSONも後の調査のため元のまま保管するため、保存成功は内容の正しさを意味しません。1ファイル1MB、合計64MB、10000ファイルまで。リンクされたファイルは拒否します。

対象はこのフォルダー直下のJSONだけです。記憶・計画・書出した学習データセット・実験結果は含まれません。GUIと復元機能は未実装です。処理中の全ファイルを同一時点で固定する仕組みではないため、比較・採点を止めてから保存してください。ZIPは暗号化していないため、質問や本文を含む個人用の資料として扱ってください。

## 画面から比較記録をバックアップする（v0.77）
「資料学習 → 比較記録・採点をバックアップ…」で保存先を指定できます。既存ZIPは上書きせず、エラーを表示します。保存済みZIPは「比較記録バックアップを検査…」から選ぶと、展開せずに一覧・サイズ・内容の一致を確認します。

処理中は開始できません。別のトメリスや外部ツールから比較記録を書き込んでいる場合は、そちらも止めてください。通常の記憶・計画や、別フォルダーに書き出した学習データセット・実験結果は含みません。復元機能はまだありません。

## 取得日時と採点日時の検査
書出しと学習実験の前に、取得完了日時と採点日時がタイムゾーン付きで記録され、採点が取得後であることを確認します。個別取得確認日時や取得開始日時がある場合は、取得期間との整合性も検査します。必須日時が不明な記録は拒否し、現在時刻で埋めません。時計のずれがある場合は時計と記録を確認して再取得・再採点してください。記事の更新日や出来事の発生日とは別の検査です。

## 評価結果の内訳
学習実験の結果画面には、検索順固定より報酬が高い／同じ／低い件数と、概要・具体的質問別の平均差を表示します。質問ごとの値と対象グループ別の値は保存結果JSONのevaluationに含まれます。対象グループを等しく重み付けした平均差は、同じテーマの質問数が多い影響を抑えて確認するための値です。どの値も正答率や統計的有意差ではありません。

評価結果を見ながら設計を繰り返し調整した場合、その課題は最終評価用には使わず、新しい未使用課題を用意する必要があります。

## 自動収集が取得経験を使う（v0.78）
トメリスを再起動して「資料学習 → 自動収集のテーマ・結果」を開くと、取得経験の件数と次の優先順が表示されます。停止中なら「再開」で収集を開始できます。停止設定を勝手に変更することはありません。

対象名完全一致と中点・全半角の表記違いを許容する探し方について、本文・引用を取得できたかを記録し、次の収集の優先順を調整します。失敗したらもう一方を試します。経験は再起動後も引き継ぎます。従来の収集上限・待機時間は維持し、アプリ起動中のみ動きます。

これは取得方法の限定的な適応です。内容の正しさや会話の知能を学習したわけではなく、Ollamaモデルの重みは変更しません。実ネットの精度向上は未検証です。retrieval_experience.jsonは経験専用で、現時点では通常バックアップに含まれません。

## 話題を続ける（v0.81）
調査後は「料金は？」「メリットは？」「使い方は？」「もっと詳しく」のように短く続けられます。引き継いだ調査対象を回答の冒頭に表示します。別の対象名を入れると新しい質問として処理します。「話題を変えて」「キャンセル」でも引き継ぎを解除できます。
普段の相談への「もっと詳しく」は直近の会話を使って続けます。「それは？」だけでは内容が曖昧なので確認します。すべての省略表現を理解するものではなく、取り違えた場合は対象名を明示してください。

## 取得経験の失敗理由
新しい経験記録は、候補なし・引用根拠なし・本文取得エラーを区別します。本文取得エラーは保存しますが、次の方法の優先順を決める成功率計算から除外します。過去の理由なし記録は書き換えず保持するため、過去分まで通信失敗を判別したわけではありません。
