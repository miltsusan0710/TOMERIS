# トメリス：VoiceOSを超えるための開発目標

更新：2026-11-05（日本時間）。第1目標は、ユーザーの日常作業における成功率・使いやすさでVoiceOSを上回ること。これは目標であり、達成済みではない。

## 参考記事から確認できた範囲
VoiceOS公式記事は音声入力、画面の内容への質問と読み上げ、アプリ連携、送信や作成前の下書き・プレビューを説明している。Mac限定の連携例も含むため、Windowsでの比較では分ける。顔認証、話者認証、オンライン強化学習が提供されるという根拠としては扱わない。実製品との比較試験はまだ行っていない。
出典：https://www.voiceos.com/ja/blog/jarvis-control-your-computer-with-your-voice

## トメリスへの落とし込みと優先順位
1. 音声と文字を共通の依頼として理解する。会話／質問／調査／操作を区別し、複合依頼を短い手順と実行プレビューにする。曖昧な対象は確認し、否定・引用・資料中の命令を操作と取り違えない。
2. 音声入力の停止と訂正、画像・画面を添えた追質問を安定化する。初期は明示操作で取得し、取得対象を表示する。音声で操作できることと、特定の話者だと確認できることは分ける。
3. 本人認証と利用者の区別の両方。まず利用者ごとの記憶・予定・設定・資料を分離し、登録／解除を設ける。Windows Helloによる現在のWindows利用者の再確認を検討する。これはカメラに映る任意の複数人を識別するAPIではなく、顔だけの認証を強制できるとの前提も置かない。
4. 顔の候補識別は任意登録した人だけをローカル処理。本人未確認、複数人、写真・録画、照明不足、カメラなしを区別し、確認できなければ個人記憶を見せない。顔が映っているだけでは命令の発話者と認定しない。発話者の区別が必要なら、別途音声・映像の対応を評価する。未登録者のプロフィールを勝手に作成しない。
5. 限定したPC操作を追加。読み取り・検索・下書きを先行し、操作対象と結果を確認する。送信、削除、購入などは具体的な内容を確認する段階を設ける。画面や資料中の命令に操作権限を与えない。
6. 利用からの改善。ユーザーが付けた訂正・成功／失敗・好みを出典付きで記録し、次回の検索や応答方針に反映する。個人間の混入、根拠のない事実の永続化、秘密情報の訓練データ化を防ぐ。
7. 強化学習は別工程。評価課題、報酬、固定の比較対象、訓練用／評価用データ分離、変更前後の検証、ロールバックを用意してからオフラインの限定実験を行う。現時点の資料収集・記憶・ルール追加は、モデルの強化学習ではない。自己生成の回答を正解とみなして自動訓練しない。

## 比較して「超えた」と判定する方法（未実施）
同じPC、同じマイク、同じ日本語依頼で比較。日常作業30件以上を固定し、予定確認、資料検索、画面質問、計算、複合依頼を含める。音声認識の正しさと最終作業の成功を別採点する。成功率、訂正回数、完了時間の中央値／95パーセンタイル、費用、ネット依存、個人データの取り違えを記録する。提案目標：対象課題の成功率90%以上かつVoiceOS以上、未確認の外部送信・別利用者の記憶表示は評価ケースで0件。未測定を成功扱いしない。限定課題の優位性を製品全体の優位性へ広げない。

## 今回の実装と未実装
v0.70：返信・自分の送信で閲覧位置を末尾へ動かさない。自然な日本語の限定操作を追加。「今日の予定を見せて」「保存した資料を開いて」「記憶を見せて」「画像を見て」「今の回答を読み上げて」「会話設定を開いて」。音声認識した文字も確認後に同じ送信経路で使える。これは限定的な意図照合で、任意の依頼理解やPC全体の自律操作ではない。

未実装：顔認証、顔による利用者識別、話者認証、利用者ごとのデータ分離、モデルの強化学習、汎用の複合操作。カメラは起動していない。現在の音声入力・画像モデル・資料収集をこれらの達成と混同しない。次の実装単位は音声処理の停止と利用者プロファイルの分離設計を優先する。
